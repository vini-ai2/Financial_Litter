# Security Policy

## Supported Versions

Security fixes are intended for the actively developed version of Finlitter on the `main` branch.

Other versions may not receive security updates.

## Reporting a Vulnerability

If you discover a security vulnerability in Finlitter, please report it privately rather than opening a public GitHub issue.

Include the following information where possible:

- A description of the vulnerability and its potential impact.
- The affected component, endpoint, or file.
- Steps to reproduce the issue.
- Proof-of-concept material, if safe to share.
- Any suggested remediation.

**Private reporting contact:** [Insert a monitored security contact email or configure GitHub Private Vulnerability Reporting.]

Please do not include real user data, production credentials, or other sensitive information in your report.

## Response Process

The maintainers will review reports, assess their severity, and work on a fix where appropriate. Reporters may be contacted for additional information.

Response and remediation timelines depend on the severity and complexity of the issue.

Please allow the maintainers a reasonable opportunity to investigate and address a vulnerability before publicly disclosing it.

## Scope

This policy applies to security vulnerabilities in Finlitter's own code and maintained components.

Third-party dependencies remain subject to their respective security reporting processes.

## Responsible Disclosure

Please make a good-faith effort to avoid privacy violations, data destruction, service disruption, or access to data that does not belong to you.

This policy does not grant authorization to access systems or data without permission.
